Q11. Before writing any code, brainstorm your plan of attack and sketch how you might decompose the work into smaller tasks. Briefly describe your decomposition strategy.
A11. First, we will fix the lettersOnly function by using tests to determine the issue. Next we will tackle writing the soundex function. We will use the lettersOnly function to get the letters, then replace each letter (except the first which we will ensure is uppercase) in the string based on the digit from the table. Then remove adjacent duplicate numbers and discard 0s. If the code is longer than 4 characters we will drop the end so that is of length 4. If it is too short, we will add 0s until its length 4.

Q12. Think about one or more examples of a class of names that the Soundex system might not work well for. Explain what this class of names is and why the system might incorrectly group them or mis-categorize one of the names.
A12. Names that are quite long would have the last parts of them cut off in the soundex code. Also, names written in other alphabets that are outside of the ASCII realm would have no representation in the current soundex model. The soundex system may group long names that sound similar at the beginning of the name, but are vastly different in the rest of the name. People who have multiple last names would only be able to be grouped by one of them as the rest would likely be truncated.

Your boss suggests using Soundex and notes that the algorithm is only expected to work for ASCII-encoded strings, since supporting Unicode would require extra work and time. What would your response be and why? What representational harms might result from building a system that exclusively uses Soundex and/or ASCII?
A13. In this situation we would advise against using only ASCII characters for soundex. We think that switching to Unicode would be better to be more inclusive and representative of other languages. We also think the soundex should be longer so that it is representative of names with more syllables. Sticking only to ASCII would limit our acessibitility, so we would propose to our boss that the work to support Unicode is worth it.
