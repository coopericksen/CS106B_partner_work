Warmup
------

Q1. Looking at a call stack listing in a debugger, what is the indication that the program being debugged uses recursion?
A1. The debugger shows multiple instances of the same function that were called from the same line. The variable 'n' within each function call holds a different value which also points to recursive behavior.

Q2. Subtract the innermost level number from the outermost to get the maximum count of stack frames that fit in the capacity of the call stack. How many stack frames fit in your system's call stack?
A2. Our debugger showed 9,999 system calls as the maximum of stack frames that can fit in our system call stack.

Q3. Describe how the symptoms of infinite recursion differ from the symptoms of an infinite loop.
A3. An infinite loop will cause unexpected behavior with little performance cost, while infinite recursion continuously adds calls to the stack wasting memory and causing the program to crash quickly.

Q4. In place of selecting values over a defined range, an alternate approach would be to randomly select values for base and exponent. Such a test case would test something different each time you ran it. This test approach is part of a larger approach known as "fuzz" testing. What do you see as possible benefit and downside of randomness being used in a test case?
A4. Random tests may reveal edge cases that the programmer was unaware of. A downside is that it may be harder to track which parts are working and which parts need to be fixed with random tests each time you run the program.

Q6. Explain how the recursive structure of `recPower` results in a Big-O runtime of `O(logN)` relative to the size of its `exp` argument.
A6. The recursive structure takes half of the exp argument with every recursive call which results in this O(logN) runtime we are observing.

Merge
-----

Q8. Give a rough estimate of the maximum length sequence that could be successfully merged on your system assuming a recursive implementation of `binaryMerge`.
A8. We saw that our stackFrame could hold around 9999 stack frames before reaching stack overflow. If each number requires one recursive call, then we estimate that the sum of lengths of a and b must be less than 9999.

Q9. What would be the observed behavior if attempting to recursively merge a sequence larger than that maximum?
A9. The program would crash as it reaches stack overflow from too many recursive calls on the stack frame.
